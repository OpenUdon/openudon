# Result V10 - Adaptive Evidence-Grounded Workflow Authoring

OpenUdon now uses an unlimited dependency-frontier interview backed by
Authoring's `authoring.interview.v1` graph and round engine. Broad requests
select one confirmed active boundary; future workflows remain unnumbered,
non-executable project candidates with deferral reasons and promotion triggers.

Before questioning, OpenUdon consumes apitools' bounded local discovery for
OpenAPI/Swagger, Google Discovery, AWS Smithy, AsyncAPI, GraphQL, OpenRPC,
gRPC/protobuf, and OData. Symlinks, unsafe paths, ambiguity, duplicates, file
limits, and traversal limits are explicit evidence. Approved remote lookup is
limited to curated references plus one APIs.guru request, eight seconds, and
three metadata candidates.

Sessions, transcripts, reports, scorecards, variants, authoring-eval, and
replay now use v2 OpenUdon contracts; v1 inputs are rejected. One interview
evidence ledger replaces overlapping durable evidence collections. Complete
and incomplete proposal approvals atomically stage reviewed sources and
project/intent artifacts, promote drafts safely, and roll back collisions.
Agent mode is read-only and returns the full frontier, candidates, source
evidence, blockers, and proposed file actions. `tfconfig` and Ramen remain
unchanged.
