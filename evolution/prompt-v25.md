# Interactive Phase C Authoring And Browser Qualification

Promote the local iCoT browser experience to Phase C without reopening the
completed Phase B transport milestones. Keep one explicit loopback workspace
for one trusted operator, retain API v2 and the transactional A09 engine/write
boundary, and add no execution, accounts, folder browser, remote serving, live
Browsertools orchestration, React, or Node.

Render the complete current frontier as accessible form controls and submit
only complete rounds with the exact displayed revision. Show selected sources,
readiness, top issue, project and intent previews, proposed actions, and exact
write conflicts before approval. Require independent review and overwrite
acknowledgements and expose separate explicit final and incomplete approval
controls.

Treat lifecycle uncertainty as visible state. Preserve unsent input across
stale revisions until explicit adoption, reconcile retryable outcomes before
offering an explicit retry, retain editable controls after domain rejection,
require restart after workspace drift, lock mutation after indeterminate
failure, and preserve frozen completion for inspection. Never automatically
retry a mutation.

Promote real-browser qualification as a separate A11 milestone. Use a
build-tagged test-only Playwright-Go harness against the actual loopback
listener to prove accessibility, keyboard flow, complete rounds, both approval
modes, conflict handling, stale/drift/retry/freeze behavior, polling and
visibility timing, conditional snapshots, and narrow/zoom layout. Make it a
required sandboxed provider-free release gate without adding Playwright to the
production UI runtime.

Close Phase C review findings within A10 rather than allocating another
milestone. Validate the complete prepared output map before mutation, reserve
engine-owned artifact/state paths from source materialization, and reject
duplicate, case-insensitive-equivalent, ancestor/descendant, and remove/write
collisions. Bound pre-refresh observation to watched and current candidate
targets, hash them through a cancellable stable-file stream, and treat an
unobserved new target as missing. Add polite mutation status plus deterministic
focus after successful rounds and approval. Keep A09 historical and leave A11
at implementation-complete/pending until hosted sandboxed evidence exists.
